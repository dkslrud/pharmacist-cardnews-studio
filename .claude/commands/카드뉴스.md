사용자 입력: $ARGUMENTS

`content_brief_template.md`의 규칙(채널별 산출 규칙, 안전 규칙, 근거 표기 형식)을 따릅니다.

## 1단계. 자동 분석 (질문 없이 바로 진행)

1. 입력에서 URL을 추출합니다. URL이 없으면 URL을 달라고만 요청하고 끝냅니다.
2. 수집은 Apify로 합니다. 실행 전에 Actor, 입력값, 예상 수집량을 한 줄로 알립니다.
   - 인스타그램 게시물·릴스: `apify/instagram-scraper` (캡션, 날짜, 좋아요, 댓글, 슬라이드 수)
   - 블로그·기사·논문 페이지: `apify/web-fetch`
3. 각 레퍼런스에서 다음을 파악합니다.
   - 채널과 형식(카드뉴스/릴스/블로그), 다룬 성분·주제
   - 후킹 방식, 정보 전개 순서, 장 수·길이, CTA
   - 근거 사용 방식(논문/기관 인용 여부, 수치 출처 표기 여부)
   - 공개 반응 수치(확인된 것만), 디자인 특징(이미지를 볼 수 있을 때만)
4. 수치나 이미지를 가져오지 못하면 추정하지 말고 "미확인"으로 적고, 필요하면 캡처를 요청합니다.
5. 레퍼런스별 요약을 짧은 표 1개와 "성공 공식 / 빈틈" 각 3줄 이내로 보고합니다.

## 2단계. 질문 후 멈춤 (반드시 이 두 가지를 묻고 답을 기다립니다)

AskUserQuestion 또는 일반 질문으로 아래를 묻습니다. 입력에 이미 있는 항목은 다시 묻지 않고 확인만 합니다.

1. **타겟**: 누구에게 보여줄 콘텐츠인가요? (나이대, 성별, 상황, 고민)
2. **제품 USP**: 홍보할 제품은 무엇이고 차별점은 무엇인가요?
   - 제품명, 식품 유형(건강기능식품/일반식품), 1회·1일 섭취량과 함량
   - 공식 제품 페이지 URL 또는 표시사항 사진
   - 내세우고 싶은 점(원료, 제조, 배합 등)

레퍼런스에서 채널·성분을 확정하지 못했거나 광고 구분(자사 판매/공구/협찬)을 모르면 같은 질문에 함께 넣습니다.
질문 후에는 어떤 작업도 진행하지 않고 답을 기다립니다.

## 3단계. 답변 후 제작

1. 근거 검증: 식약처·식품안전나라 → 국내 영양소 섭취기준 → NIH ODS → PubMed 순. 원문을 열어 확인한 것과 못 한 것을 구분해 `03_fact_check.md` 형식으로 기록합니다.
2. USP 검증: 사용자가 준 USP는 공식 표시사항·근거로 확인되는 것만 콘텐츠에 사용하고, 나머지는 "확인 필요"로 표시합니다.
3. 기획: 채널이 카드뉴스면 레퍼런스에서 파악한 구조를 참고하되 문장은 복사하지 않고, 카드마다 학술·논문 근거를 붙입니다. 영상이면 컷별 스크립트(시간, 화면, 자막, 내레이션)를 작성합니다.
4. 제작·캡션·검수 순서로 진행하고, 산출물은 `cardnews_<주제>/` 폴더에 저장합니다.
